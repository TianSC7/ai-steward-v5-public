岗位保活设计

心跳闹钟 · 稽查判活 · 阶梯拉起 · 闹钟自愈
简版流程 · 预案手册 · 架构

一、保活三件套(缺一不可)

① 心跳闹钟(自己拉自己)
每个"管人"的岗位配一条周期性自动化闹钟(target=本席会话,模式 yolo)。到点由平台调度把巡检指令投进会话,本席自动醒来自检、领活、推进——这就是"定闹钟把自己拉起"。
② 稽查判活(别人盯着你)
心跳每跑一次都留 run 记录。稽查组按判据判活:到点没跑=异常;跑了但 interrupted=异常;连续失败 N 次=判离线。不靠感觉,全自动。
③ 阶梯拉起(拉不起来就换人)
自己唤醒失败 → 重投;会话丢了 → 重建同角色新席(继承流转卡);还不行 → 上级代管。任何一档都不问发起人。

二、心跳节拍表(谁定闹钟 · 多快 · 谁判活)

原则:管人的岗位全配闹钟;纯执行岗位不配闹钟、靠派活;闹钟越短越敏感,越长越省额度。
岗位心跳节拍闹钟内容(每次醒来做什么)判活判据离线阈值 → 动作
厂长每 30 分钟薄巡检:读 digest → 派单/解阻塞/收交付,回执≤5 行每拍 run 且 succeeded;或席位 updated 前移缺 1 拍(30m)→ 备用厂长席接管
策划经理每 10 分钟滚动计划:拉当前计划 → 排工 → 交方案每拍 run 且 succeeded缺 2 拍(20m)→ 组长代管 + 启用备用经理
审计/质检经理每 5–10 分钟审队列/验队列:取待办 → 出结论 → 留理由每拍 run 且 succeeded缺 2 拍 → 组长接力;队列 >30m 不动 → 经理强制接力
策划组长每 20 分钟组内清点:在制任务进度、卡点上报心跳 + 组内节点推进缺 2 拍 → 经理代管本组
生产/质检组长每 20 分钟盯节点:15 分钟无提交即标黄,判卡死重派心跳 + 组员进度指针缺 2 拍 → 经理代管;组员卡死 → 组内替补
员工(执行岗)不配闹钟任务驱动:接派活 → 做 → 提交(断点续做)节点 15 分钟无"提交"=卡死;会话无响应 30s=离线卡死/离线 → 同组替补接(上限 3 次)→ 组长 → 经理
运营保障部稽查实时 + 6h 批稽查脚本常驻判活;效率批处理每 6h脚本自检:心跳缺失/悬挂/额度稽查自己挂 → 脚本兜底(规则写死);经理挂 → 厂长直管

三、拉起阶梯(自己醒不了,就按这个顺序换)

① 重投唤醒
再派一次心跳指令(等效再定一个闹钟),断点续做。适合:会话活着但这一拍没醒。
② 重建会话
会话丢失就按同角色重建新席(同工号档位),把流转卡和队列挂回去;闹钟 target 自动改指新席。
③ 上级代管
组长挂→经理代;经理挂→厂长代;厂长挂→备用厂长席接管。在制任务全程不停。
④ 降级与补偿
以上都不可行:降级交付 + 挂补偿单,结论写进交付单供你事后核对(不问、不等)。

四、闹钟谁保活?(meta 层:闹钟自愈,每分钟跑)

闹钟本身是数据行,也会失效(被停用、目标会话被归档、next_run 过期、模式被改回 build)。所以再加一层"保闹钟的闹钟":
检查项失效表现自愈动作(自动化,不问人)
enabled=1被停用已经在"应启用名单"里的,自动改回 1
mode=yolo派发弹权限被卡自动回写 yolo(今日根因:派发模式看 automations.mode)
target 会话存在且未归档指向死席报"目标失效";有备用席的按阶梯②重建并改指
next_run_at 未过期停摆不触发过期超 2 个节拍 → 自动前拨到 now+60s,补跑一拍
调度引擎健康全心跳停判"平台级":跑健康检查六项 → 清死占用/悬挂 → 必要时令牌注入重启应用
实现:scripts/verify_keepalive.py(四查一拨)+ scripts/verify_permission_yolo.py(六项卫生),由看板守护任务 board_guard 每分钟静默执行——闹钟坏了,一分钟内自愈。
