一、并发四层与 WIP 上限(在制品限制)

并发的单位是"层":订单层并行、部门层并行、席位层串行、平台层限流。每层都有硬上限,超了就排队,不硬塞。
并发层并行单位上限(日班)上限(夜班)超限怎么办
订单层同时推进中的父订单≤ 3≤ 5第 4 单起排队(queued),不影响在制单
部门层·生产3 组 × 3 员工 = 9 执行位99组内排队;跨组借调需经理批
部门层·策划计划组 + 方案组22方案排队;计划始终优先(计划是派工依据)
部门层·审计/质检各 1 组长 + 员工2 并发审/验位2队列积压 >30 分钟 → 员工加开验位(闸不跳过)
席位层1 席同时只跑 1 个回合串行串行平台派发是抢占式的:同席连派会打断在飞回合(已实测)→ 同席待办 ≤3,超了拆新席
平台层全场活跃席 + 模型配额活跃席 ≤7≤10(免费额度)超额排队;单 lane 配额:R4×6 / GLM×3 / STEP×3 / NEX×3 / 外包×1

二、并发冲突怎么处理(对照表)

冲突类型典型场景处置(全部自动)
同卡争抢两个员工同时领同一张卡claim 原子锁:先到者领到(attempts+1),后到者锁定失败 → 回队列等下一拍,不中断先到者
同文件并发写两单同时改同一产物文件锁 + 原子写(临时文件+改名);冲突写 → 后者拿锁失败排队;同秒备份自动留
版本冲突子需求 A/B 各改一版版本冻结 + 发布闸串行合并:先过质检的版本为准,后到者 rebase 到该版本上重验
资源冲突额度/模型池打架预算闸:超配额任务排队或降级模型;长批处理让给夜间免费档
平台抢占同席多派发 → 在飞回合被打断串行纪律:同席待办≤3;重要长令放心跳空窗(如 30min 心跳的 29 分钟窗口);被打断的回合视为断点,重投续做
重复执行重试导致同一节点做两次节点幂等:按 MD 卡"提交"指针判重;第二次只做校核不覆盖

三、调度算法(每拍派工的判定顺序)

① 优先级
P0 急单 → P1 常规 → P2 缓办;同级先到先派
② 依赖检查
依赖未完成不派;依赖失败 → 重规划(replan)
③ WIP 闸
任一并发层到上限 → 该单排队,派做别的
④ 退避与公平
重试指数退避(上限 3 次);同优先级轮转,不饿死任何 lane
观测(WIP 大盘):在制数 / 各层占用 / 队列深度 / 阻塞数 / 平均等待时长 —— 看板实时显示,效率分析每 6h 出并发利用率与瓶颈 Top3。

四、日班 / 夜班怎么安排

席位常驻不换人,换的是"班次配置":节拍、并发上限、任务类型、发布策略。夜班 23:00–09:00 吃免费额度(夜间 3 亿 token),把重活批处理全部压到夜里。
日班 08:00 – 23:00
  • 模型:主力高质量模型;侧重需求确认、方案/审计、重要生产、最终交付
  • 心跳:厂长 30min / 策划 10min / 审计·安全 5min(基准节拍)
  • 并发:订单 ≤3;活跃席 ≤7;生产 9 执行位
  • 发布:白天走发布闸,允许终审放行
  • 人工零接触:除交付单外不出现在你面前
夜班 23:00 – 09:00
  • 额度:夜间免费档(智谱 23:00–09:00 3 亿 token),重活批处理专场
  • 任务类型:长文/批量测试/扫描清洗/经验整理/文档对账/次日方案预研——不收高风险新需求
  • 心跳:基准节拍 + 夜班巡检 10min 一条(防静默)
  • 并发:订单 ≤5(免费额度充裕),活跃席 ≤10;单席待办仍 ≤3
  • 发布冻结:夜班只入"发布候选",不批准对外发布(白天终审)

五、交接班规矩(22:50 / 08:50)

时点动作交班单内容(≤10 行)
22:50日班→夜班在制清单(单号/卡点)、未闭合驳回、挂起原因、额度余量、夜班重活排程(按免费额度分配)、发布候选清单
08:50夜班→日班夜班产出清单、批处理结果、夜间告警与处置记录、发布候选待终审、当日产能预判
交班确认接班组 5 分钟内逐项打勾确认;有疑项当场挂"交接争议"小单,不带着疑问开工

六、实测教训(已入纪律)

教训纪律
平台对同一会话的派发是抢占式连续投递会打断在飞回合(19:50 实测)→ 同席串行,待办≤3,长令放心跳空窗
闹钟被停用/模式被改 → 派发即卡verify_keepalive 每分钟四查一拨(mode/enabled/target/next),target 已死的遗留只隔离不复活
旧席归档后心跳指向死席席位重建后闹钟自动改指新席;交接单必查 target 存活
并发:四层 WIP 上限 + 冲突对照 + 派工四步 · 班次:席位常驻换配置,夜班吃免费额度出重活,发布夜间冻结
