二、主流程(需求到交付)发布闸为硬闸

01 · 入口
你提需求
02 · 厂长
需求契约
目标/子需求/验收/不做/风险/预算/WIP/截止/路由 · 全部自动确认,不询问发起人
03 · 策划
滚动计划 + 按子需求出方案
04 · 审计
审方案覆盖验收标准
05 · 生产
按通过方案产出
06 · 质检
逐条验验收标准
07 · 发布闸(硬)
质检过 + 审计无未闭合 + 稽查无阻断 + 版本冻结 + 回滚方案
08 · 厂长
最终交付单 → 你验收
驳回回路:审计驳回 → 回策划;质检驳回 → 回生产。重试有上限,超限升级厂长,不无限循环。
稽查边界:稽查发现异常不直接改产品结论,只做隔离 / 重派 / 补偿。
变更单:需求变更唯一入口=厂长,变更留痕进 MD 卡"变更记录"节。

三、工单与追溯一需求一工单 · 一工单一个 MD 流转卡

秒级留痕(每个节点)
  • 进入 / 分配 / 开始 / 提交 / 离开
  • 驳回 / 恢复 / 发布
  • MD 只追加不覆盖;变更写"变更记录"节
  • 同步写结构化字段表,供看板/统计/日报
核心指标(每工单)
  • 处理时长 / 等待时长 / 流转时长
  • 驳回次数 / 返工次数 / 超时数 / 挂起次数
  • 额度消耗 / 准时交付率

四、异常不停线(写死原则)只停出问题的点

处置顺序
  • 1 隔离异常点(子需求/Agent)
  • 2 重派 / 替补
  • 3 绕行
  • 4 降级交付
  • 5 挂补偿单
  • 6 记录秒级时间戳
父订单状态与发布分批
  • 推进中 / 部分可交付 / 有条件交付 / 全部完成
  • 已通过质检+审计的子需求先进发布候选
  • 未通过挂"待补偿",不阻塞已通过部分
  • 仅不可逆损害硬停:数据破坏 / 越权 / 对外发布安全风险

五、策划滚动排产 + 运保部双组

小时计划板(三栏)
  • 当前 1 小时:锁定执行,派工依据(仅阻断异常可改)
  • 短期 5 小时:每小时滚动,排资源/依赖/借调
  • 长期 12 小时:产能/额度/瓶颈预判,不承诺
  • 防抖动:冻结窗口 / 变更阈值 / 依赖优先 / WIP 上限 / 补偿池不占当前计划
稽查组(实时/近实时)
  • 抓:心跳缺失 / 无响应 / 超时 / 挂起
  • 抓:前台空转 sleep / 长任务不后台化 / 额度空耗 / 无限重试 / 伪等待
  • 抓:WIP 积压 / 版本冲突
  • 闭环:发现→告警→中断/隔离→后台化或重派→恢复确认→记录违规→复盘
  • 黄灯报组长/经理;红灯报厂长+运保部;阻断升级你
效率分析组(每 6 小时,每天 4 批)
  • 前 3 批:快照 + 异常清单 + 指标(不派改善任务)
  • 第 4 批:完整日报 + Top3 瓶颈 + Top3 驳回 + 最多 3 个改善项 + 昨日改善关闭情况
  • 改善项必须:责任人 / 截止 / 验证结果
  • 统计:计划达成率 / 短期命中率 / 长期偏差 / 抖动次数

六、专属记忆库(四层)与自我迭代

四层结构
  • 事实层:工单/时间戳/驳回/质检/稽查,结构化表
  • 经验层:驳回案例/优秀方案/验收模板/异常处置,向量库,标 待验证/已验证/已过期
  • 规则层:SOP/模板/路由,版本化
  • 改善层:改善项/责任人/截止/验证结果,闭环跟踪
防自我污染规则
  • 低质量/未验证/被驳回未修复内容不进经验层
  • 记忆只标过期,不物理删除历史
  • 多次验证有效才可提案升级为规则
  • 规则变更:AI 提案 → 厂长审批 → 审计复核,不能自动改

七、无人值守与人工闸门只有四类找你

全自动范围
  • 日常流转 / 派活 / 驳回 / 重派 / 替补
  • 质检 / 常规发布
唯一人工接触点:最终交付单(不询问、只交结果)
  • 需求确认/规则升级/发布终审/阻断处置:全部自动,不询问你
  • 不可逆风险(数据破坏/越权/对外发布):该项自动搁置不硬做,其余照跑
  • 你只看:最终交付单 + 事后核对结论
你每天只看:第 4 批日报、红灯/阻断关闭情况、厂长《最终交付单》。

八、最终交付单(厂长汇总 → 你验收)

组成部分内容
订单与目标订单号 / 需求目标 / 交付物清单及版本
三方结论质检结论 / 审计结论 / 稽查结论
交付与补偿已交付 / 未交付 / 补偿计划
风险与回滚遗留风险 / 回滚方案 / 厂长交付意见
你的验收接受 / 有条件接受 / 退回
发布闸硬条件:本次子需求质检全过 + 审计无未关闭驳回 + 稽查无阻断 + 版本冻结 + 有回滚方案。

九、建设顺序与验收标准

1工单状态机 + MD 模板 + 结构化字段表
2组织权限矩阵 + 需求契约 + 交接单
3主流程流转 + 驳回 + 变更单
4稽查基础规则 + 异常不停线 + 补偿池
5策划滚动计划板
66 小时批处理 + 第 4 批日报 + 改善闭环
7向量记忆库 + 规则审批
8发布闸 + 最终交付单
9先 L2 半自治,稳定后 L3 异常驱动自治
验收标准
  • 每条需求可追溯到秒级节点耗时
  • 异常不阻塞父订单和其他子需求
  • 日报自动生成且有改善闭环
  • 规则变更必须审批留痕
  • 发布有硬闸和回滚方案
  • 厂长是唯一交付口
一句话总纲
  • 按 MES 工单模式搭建:厂长唯一入口,部门三层编制
  • 一需求一工单,MD 秒级留痕
  • 异常不停线,策划每小时滚动排产
  • 运保部实时稽查 + 每 6 小时效率分析 + 向量记忆库迭代
  • 发布过硬闸,厂长最终交付
